# 纯推广内容方案交付规范

这个规范适用于 `COMPLETE_PROMOTION_PACKAGE`。交付内容包括产品推广主题、平台推荐、平台原生适配、图文案例、视频案例、潜在客户问题和用户案例。

## 零、使用前提

默认产品已经由开发者完成，并由开发者判断为有意义、有目标用户且值得宣发。交付物只回答产品在自媒体上“讲给谁、讲什么、怎样写、怎样拍、适合哪些平台”，不评估需求真伪、PMF、商业价值或项目是否应该继续。素材和证据不足时，只标记需要补充的宣发材料或使用明确标注的样例场景，不输出“没人会用”“产品没意义”“不值得推广”等结论。

## 一、产品内容定位

包括：

- 产品名称。
- 一句话产品说明。
- 主要用户。
- 典型使用时刻。
- 产品解决的具体问题。
- 最适合展示的结果。
- 内容的整体语气和视觉感觉。

## 二、内容方向

包括：

- 国内或海外。
- 海外时注明主要国家、地区或语言。
- ToC、ToB 或 Hybrid。
- 主受众和次受众。
- 为什么采用这个内容方向。
- 国内与海外内容分别需要怎样表达。
- ToC 与 ToB 内容分别强调什么。

这里同时为后续平台推荐提供依据，但不提供发布时间和发布节奏。

## 三、平台推荐与平台适配

包括：

- 一个主平台和两个备选平台。
- 每个平台的目标受众、内容角色、适合的产品亮点、适合的内容形态和推荐理由。
- 一到三个暂不优先平台及原因。
- 六套图文与八套短视频的首选平台标注。
- 前两篇完整图文在三个推荐平台上的原生版本。
- 前两条完整视频在三个推荐平台上的原生版本。
- 每个平台版本的标题、内容描述、完整配文和 Tags。

每个平台版本必须改动标题或开头、结构、文案或口播、画面顺序等核心内容。只改尺寸或平台名不算适配。

## 四、主要产品亮点

选择三到五个亮点。每个亮点使用完整亮点内容卡：

```text
亮点名称：
目标人物：
使用时刻：
原来的状态：
产品动作：
最终结果：
需要放大的细节：
图文怎样展示：
短视频怎样展示：
所需素材：
```

## 五、潜在客户问题

至少提供八个潜在客户最关心的问题，优先覆盖：

- 产品适合谁。
- 解决什么具体问题。
- 使用者怎样开始。
- 能看到什么真实结果。
- 答错或失败后怎样继续。
- 内容范围和适用边界。
- 与常见替代方案有什么区别。
- 家长或决策者应该怎样判断。

每个问题包括目标客户、发生场景、顾虑、产品证据、图文表现、视频表现和所需素材。开发故事不进入默认完整推广包。

## 六、用户案例内容

根据现有材料选择至少三种内容：

- 完整用户案例。
- 匿名用户故事。
- 创始人实测。
- 样例使用场景。
- 一句话反馈展开。

每个内容写清人物或团队、场景、原状态、产品动作、结果画面、图文页序、视频分镜和所需素材。

## 七、内容主题

选择三到六组主题：

- 问题场景。
- 产品结果。
- 开发过程。
- 用户与样例。
- 教程与方法。
- 对比与选择。
- 创始人观点。
- 产品更新。

每组说明：面向谁、主要讲什么、最重要的画面、适合图文还是视频、可以延伸哪些内容。

## 八、100个具体内容角度

交付100个针对当前产品改写的角度，至少覆盖玩法、奖励、客户视角、题库、开发过程、实际使用者和强流量七类。筛选顺序中“强流量”放在“实际使用者”之后。开发过程只作为内容池备选，不进入默认图文或视频案例。每个角度包括：

```text
角度名称：
内容分类：
面向谁：
发生在什么场景：
核心内容：
产品怎样出现：
最重要的画面：
适合图文还是视频：
所需素材：
可延伸内容：
```

不能只给100个通用标题；所有标题都要具备自媒体点击理由，并与当前产品事实相连。生成后必须整体去重和去水分，删除重复、空泛、换词复述或只对开发者自嗨的凑数角度，再补足到100个。

每个角度的描述必须是面向潜在客户的发布口吻。禁止写成“展示某功能、证明某结果、解释某机制、通过某画面、围绕某问题”的制作说明；改写为人物、动作和结果连续出现的一到两句自然中文。

“强流量”只负责提高点击意愿，可以使用惊悚感、夸张感、冲突、反差、倒计时、失败后果和结果悬念。标题与正文仍必须展示真实产品画面、真实动作或真实结果；可以放大真实冲突，不能编造产品能力、用户评价、学习效果、增长数据或不存在的后果。

## 九、六套图文推广方案

每套包括：

- 内容角度。
- 目标人物和场景。
- 三个标题。
- 国内内容至少有一个具体、自媒体化的主标题，标题使用真实动作、数字、冲突、悬念或可见结果。
- 三个标题全部达到可直接发布的自媒体获客标准。
- 国内封面默认 `2:3` 竖版，主标题直接进入画面。
- 封面文案和画面。
- 完整页序。
- 每页文案。
- 每页画面。
- 产品截图和结果图清单。
- 补充视觉。
- 正文或配文结构。
- 一句内容描述。
- 完整发布配文。
- 六到十二个与当前平台和内容相关的 Tags。
- 结尾产品说明。
- 可拆出的短图文。
- 首选平台及适配重点。

其中至少两套需要写成完整逐页文案和完整正文。

## 十、八套短视频推广方案

每套包括：

- 视频角度。
- 目标人物和场景。
- 建议时长。
- 三个开头。
- 完整内容结构。
- 分镜。
- 产品录屏清单。
- 输入和结果素材。
- 屏幕文字。
- 结果出现的镜头。
- 结尾产品说明。
- 封面和标题；国内短视频每条至少提供五个自媒体标题候选，海外短视频至少提供三个平台原生标题。
- 一句内容描述。
- 完整视频配文。
- 六到十二个与当前平台和内容相关的 Tags。
- 短版和无口播版本。
- 首选平台及适配重点。

八套都需要写成完整口播或对白、完整逐镜头分镜、屏幕文字和完整配文。全部面向潜在客户或实际使用者，不能混入开发故事，也不能只完成前两条脚本。

## 十一、Agent 提示词与 MD 交付

为当前产品生成一份可持续扩写推广内容的独立 MD，默认命名为 `产品名-Agent内容创作提示词.md`。它必须综合本方案已经确认的产品事实、核心亮点、受众、市场路线、平台、内容池和内容质量标准，让后续 Agent 能继续生成新的获客图文和完整短视频脚本。

提示词上方先写“放置说明”：优先追加到实际产品项目根目录的 `AGENTS.md`，已有文件时不得覆盖；不能自动读取 `AGENTS.md` 的 Agent，则从项目根目录或 `docs/` 读取独立 MD。完整提示词的结构与验收要求见 [agent-prompt-handoff.md](agent-prompt-handoff.md)。

HTML 报告在海外平台之后单列“Agent提示词”章节，提供完整提示词、复制按钮和独立 MD 入口。

## 十二、分批交付

当完整内容过长时：

1. 第一批交付产品定位、亮点、潜在客户问题、案例结构、100个角度、六套图文与八套视频的完整方案。
2. 同时完成两篇图文和至少四条完整短视频脚本；八条脚本必须在完整交付结束前全部完成。
3. 后续批次继续写剩余图文和短视频成品，不得停在两条完整脚本。

后续批次直接接着制作，不重复产品分析。

## 十三、完整性检查

交付前确认：

- 没有日历和发布时间。
- 有基于产品、市场和受众的平台推荐，不是热门平台罗列。
- 有主平台和备选平台的原生内容适配。
- 没有转化承接和销售流程。
- 没有指标、实验、复盘和停止条件。
- 没有把平台适配扩展成账号运营或发布计划。
- 没有评价或否定产品意义、市场价值、用户需求和继续开发的必要性。
- 产品亮点包含具体展示方法。
- 潜在客户问题都有具体产品证据回答。
- 用户案例包含完整内容结构。
- 图文包含页序和画面。
- 视频包含脚本和分镜。
- 八条视频都达到可直接拍摄的完整度。
- 国内短视频标题具有具体动作、数字、冲突、悬念或可见结果，没有停留在“产品介绍、功能演示、完整玩法、开发记录”。
- 内容池仍为100个，七类筛选齐全，“强流量”位于“实际使用者”之后，且没有以虚构结果换取点击。
- 每篇图文和每条视频都有内容描述、完整配文和相关 Tags。
- 没有独立的全局“素材清单与拍摄说明”板块；必要镜头只写在对应内容卡中。
- 默认最终交付物是可直接浏览的响应式 HTML 报告，Markdown 只作为可选内容源。
- 有项目专属的 Agent 提示词 MD，且不是带占位符的通用模板。
- HTML 最后一部分有“Agent提示词”导航和章节，提示词上方清楚回答应该放在哪里，并提供复制与打开 MD 的入口。
- HTML 的全部章节标题使用同色、放大的章节数字与英文；桌面端左栏顶部、底部分别与右侧“主标题 + 说明”对齐，不使用独立强调色徽章，手机端不溢出。
