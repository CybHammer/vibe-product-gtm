# 产品读取与内容方向判断

完整推广内容方案从产品本身开始。这个参考文件负责提取内容素材，确定国内/海外、ToC/ToB 的表达方向，并为平台选择提供依据；不延伸到发布日历、转化或数据工作。

产品读取不是产品评审。默认接受开发者关于产品有意义、已有目标用户并值得继续宣发的判断；不重新验证需求、PMF、商业价值或项目是否应该继续。这里的所有判断只服务于“自媒体内容怎样表达”。材料不足时标记缺少的宣发证据或改用明确标注的样例，不得把素材不足解释成产品没有价值、没人会用或不值得推广。

## 一、读取顺序

### 产品网址

重点查看：

- 首屏怎样介绍产品。
- 核心功能入口。
- 实际操作流程。
- 输入材料。
- 处理过程。
- 结果页面。
- 可以展示的前后变化。
- 产品已有的示例和截图。

### 本地项目或仓库

重点读取：

- 项目规则和 README。
- 页面路由和主要模块。
- 首页、功能页和产品内文案。
- 示例数据和演示流程。
- 版本记录、问题记录和设计稿。
- 可以转化为开发故事的修改。

不需要为了推广内容修改产品代码。

### 截图、录屏和口述

如果没有完整产品访问条件，整理：

- 截图分别对应哪个步骤。
- 录屏里哪几个结果最清楚。
- 用户口述中的事实、判断和愿望。
- 哪些内容还缺具体素材。


## 三、国内与海外内容方向

### 国内内容

判断依据：

- 产品主要服务中国大陆用户。
- 产品语言、业务场景和用户称呼以中文为主。
- 用户遇到的问题带有明显的国内工作或生活环境。
- 用户希望制作中文图文和中文短视频。

内容需要使用自然中文、具体场景和直接结果。不要把海外文案翻译成中文后直接使用。

### 海外内容

先确定主要国家、地区或语言市场。

内容需要重新选择：

- 用户称呼。
- 工作或生活场景。
- 产品类别说法。
- 案例背景。
- 价值表达。
- 标题、口播和视觉信息密度。

不要把中文版直译成英文后当作海外内容。

## 四、ToC 与 ToB 内容方向

### ToC

重点表现：

- 一个人遇到的具体麻烦。
- 使用前后的直接变化。
- 第一次使用就能看到的结果。
- 操作是否简单。
- 情绪、体验、效率、创作结果或日常变化。
- 用户愿意展示和分享的成果。

案例以个人的真实使用时刻为核心。

### ToB

重点表现：

- 某个岗位或团队的具体工作流程。
- 哪一步最耗时间或最容易出错。
- 产品怎样进入现有流程。
- 团队成员分别看到什么结果。
- 产品背后的方法、专业性和稳定感。
- 业务场景、交付结果和团队协作变化。

案例需要写清使用者、团队背景、原流程、产品动作和最终产物。

### Hybrid

混合产品需要确定主叙事：

- 个人先使用，团队后来采用。
- 个人负责操作，公司负责购买。
- 同一产品分别服务个人与企业。

主叙事和次叙事分别制作，不能用一篇内容同时说服所有人。

## 五、从功能中选择亮点

使用下面的转换方法：

```text
功能名称
→ 谁在什么情况下使用
→ 原来的动作
→ 产品替代或改善的动作
→ 屏幕上能看到的结果
→ 最适合的图文画面
→ 最适合的短视频画面
```

优先选择：

- 一眼能看懂的变化。
- 前后对比明显的结果。
- 用户高频遇到的情况。
- 能体现产品独特方法的功能。
- 能产生漂亮或有用成果的功能。
- 开发过程中有故事的功能。

## 六、推广素材盘点

整理为：

- 产品首页截图。
- 核心操作截图。
- 输入材料。
- 输出结果。
- 前后对比。
- 完整产品录屏。
- 局部功能录屏。
- 第一版和当前版本。
- 失败版本、Bug 画面和修复后画面。
- 创始人出镜或口播素材。
- 用户使用画面、反馈或案例素材。
- 图标、Logo、品牌色和字体。
- 需要重新制作的说明图。

最后标明每个内容角度需要使用哪一批素材。
