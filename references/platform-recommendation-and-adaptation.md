# 国内外平台推荐与内容适配

这个参考文件负责两件事：为当前产品选择合适的平台，以及把产品亮点、开发故事、用户案例、图文和短视频改成平台原生内容。它不负责发布日历、账号运营、转化承接、指标、实验或复盘。

平台判断只评价“当前产品内容与某个平台的受众、形式和素材是否匹配”，不评价产品本身有没有意义、有没有市场或是否值得继续。列出“暂不优先平台”时，只能说明内容形态、受众浓度、语言条件或现有素材不匹配，不能把平台不匹配写成对项目价值的否定。

## 一、推荐平台时先看什么

不要先列平台，再把产品硬塞进去。先判断：

- 市场：国内、海外或双市场；海外需要具体到国家、地区或语言。
- 购买对象：ToC、ToB 或 Hybrid。
- 核心受众平时在哪里获取同类信息。
- 产品结果能否在几秒内看懂。
- 产品是否需要完整教程、专业解释或技术背景。
- 亮点更适合截图、卡片、录屏、真人口播还是长文。
- 开发过程是否有可讲的冲突、取舍和技术细节。
- 用户案例更像个人体验、业务工作流还是专业方法。
- 现有账号、语言能力、出镜条件和素材是否支持该平台内容。

完整方案默认推荐一个主平台和两个备选平台。若产品明显只适合一个垂直社区，可以减少数量并说明原因；不要为了凑数推荐泛平台。

## 二、平台推荐卡

每个推荐平台使用同一张卡：

```text

适合的市场与受众：
这个平台在本方案中的内容角色：
适合承载的产品亮点：
适合承载的开发故事：
适合承载的用户案例：
优先内容形态：
标题或开头特点：
画面和素材重点：
文字与口播感觉：
产品出现方式：
不适合发布的内容：
推荐理由：
```

同时列出一到三个“暂不优先平台”，说明是受众不匹配、产品不够可视化、内容过于复杂、素材不足，还是平台形态不适合。不要给发布频率和运营动作。

## 三、国内平台判断

### 小红书

优先考虑：

- ToC 效率、创作、学习、生活方式、设计、旅行、个人管理等容易形成场景和结果的产品。
- 面向自由职业者、创作者、职场人、小团队使用者的轻量 ToB 产品。
- 有清晰前后对比、教程、清单、结果卡片和产品截图的内容。

原生适配：

- 标题写清人群、场景、麻烦或结果，不用宽泛产品口号。
- 封面只放一个信息中心，优先展示结果或冲突。
- 图文使用逐页推进：场景、原状态、产品动作、结果、关键细节。
- 短视频保留口语感，产品界面和结果要适合手机观看。
- 开发故事从“为什么做、删掉什么、解决了哪个真实麻烦”进入。

### 抖音

优先考虑：

- 三到五秒内能够出现明显结果、变化、冲突或惊喜的产品。
- 能用竖屏录屏、真人口播、场景表演或连续操作展示的产品。
- ToC 直接体验，以及流程较短、结果明显的 ToB 工作流。

原生适配：

- 第一段画面直接出现问题或结果，避免先介绍团队和技术背景。
- 一条视频只证明一个亮点。
- 录屏放大关键区域，字幕用短句，不把桌面端完整界面缩成看不清的小窗。
- 开发过程需要有具体冲突、失败画面或版本变化。
- 复杂 ToB 产品拆成一个岗位、一个任务、一个可见结果。

### Bilibili

优先考虑：

- 需要完整演示、教程、技术解释、对比或开发过程的产品。
- 开发者工具、AI 工具、生产力软件、创作工具和专业工作流。
- 创始人能够讲清设计决定、失败版本和实现方法的产品。

原生适配：

- 标题包含明确任务、结果、开发挑战或验证问题。
- 结构允许先展示结果，再完整演示过程和关键取舍。
- 产品录屏保持可读，必要时分章节或增加局部放大。
- 开发故事可以保留更多技术细节，但始终要让观众看到实际产品。
- 图文动态或专栏版应提炼成流程图、截图组和关键结论，不能直接粘贴视频口播。

### 微信视频号

优先考虑：

- 创始人信任、专业身份、行业经验和熟人传播较重要的产品。
- 面向企业经营者、团队负责人、专业人士或本地业务的产品。
- 真人讲解加产品证明、客户场景和完整工作流片段。

原生适配：

- 先说清谁遇到什么业务或生活问题，再让产品进入。
- 口播语气稳、信息完整，减少只靠网络梗推动内容。
- 画面结合真人、产品操作和结果材料，不能全程只放人像口播。
- ToB 案例写清岗位、任务、产品动作和交付物。

### 微信公众号

优先考虑：

- 需要长文解释的 ToB 产品、专业工具、复杂教程、完整案例和版本故事。
- 已有微信关系、行业读者或创始人个人影响力的产品。
- 能提供大量截图、流程图、结果样张和开发细节的内容。

原生适配：

- 标题聚焦一个业务问题、产品决定、案例或完整方法。
- 正文使用清晰小节，场景与结果在前，技术解释随后。
- 每个关键结论配界面、流程或结果证据。
- 用户案例使用完整叙事，不压缩成一句评价。
- 结尾总结产品适合谁、完成什么任务，不加入私域或销售流程设计。

### 知乎

优先考虑：

- 用户会主动搜索、比较和深入理解的问题。
- AI、技术、效率、职业、教育、商业和专业工作流产品。
- 创始人具备真实经验、方法、案例或开发判断的内容。

原生适配：

- 从一个真实问题出发，先完整回答问题，再让产品作为方法或实例出现。
- 标题和开头强调问题、判断或经验，不写纯广告式介绍。
- 使用原因、过程、证据、边界和结果组成长内容。
- 开发故事适合展开“为什么这样做”“哪个假设错了”“最后如何验证”。
- 产品身份和创始人关系保持透明。

### 即刻、少数派、掘金、CSDN、V2EX及垂直社区

只在受众高度匹配时推荐：

- 即刻：独立开发、AI、创始人观点、开发过程和产品观察。
- 少数派：生产力工具、数字生活、完整使用方法和长期体验。
- 掘金或 CSDN：开发者工具、API、代码工作流和技术实现。
- V2EX：面向技术用户的真实产品、开发问题、工具分享和反馈讨论。
- 行业社区：受众浓度高于泛平台时优先，但必须按该社区语境重新写。

社区版本要贡献完整经验或方法，避免把产品宣传稿原样粘贴过去。

## 四、海外平台判断

完整双市场报告中的海外平台必须单列一个部分，不能只在国内平台后补两句翻译建议。先回答国内内容能否复用，再按以下角色组织：

- 面向客户的短视频触达。
- 面向客户的图文、视觉搜索和完整说明。
- 面向早期用户的新品发现。
- 面向开发者或垂直用户的社区验证。
- 面向可玩产品、游戏或开源项目的实际分发。

客户获客路线与产品发现/反馈路线要分开。Product Hunt、Show HN、Indie Hackers 等平台可以讲 Maker Story，但这些内容不进入默认客户图文和视频案例。

### TikTok 与 Instagram Reels

优先考虑：

- 视觉结果明显、能快速演示、具有创作性或日常场景的 ToC 产品。
- 能用竖屏录屏、真人反应、前后变化、教程或挑战表达的产品。

原生适配：

- 开头立刻出现结果、问题或视觉变化。
- 使用竖屏构图、短句字幕、快速但可理解的操作画面。
- TikTok 版本可更口语、更像原生创作者演示；Reels 版本可强化画面完整度和可保存步骤。
- 同一素材需要分别改开头、字幕密度、镜头节奏和配文，不能只换平台名称。

### YouTube Shorts

优先考虑：

- 一个亮点可以在短时间内完整演示的产品。
- 希望同时积累产品演示、教程和长视频入口的产品。

原生适配：

- 标题与开头围绕一个明确任务或结果。
- 画面必须独立成立，不能依赖另一条长视频才能看懂产品价值。
- 可以从完整教程中重构一个短任务，但不是机械裁切。
- 具体时长上限、音乐和版权要求需要在制作时核对官方规则。

### YouTube 长视频

优先考虑：

- 复杂产品演示、教程、比较、技术解释和完整开发故事。
- ToB 工作流、开发者工具、AI 工具和需要搜索沉淀的内容。

原生适配：

- 标题承诺一个完整任务、验证或判断。
- 开头先展示最终结果和观看价值，再进入过程。
- 使用章节化脚本、清晰录屏、局部放大和结果复盘。
- 产品应贯穿任务，而不是只在片尾出现一次。

### Pinterest

优先考虑：

- 适合竖版图文、清单、教程、家长选择指南和视觉结果卡的 ToC 产品。
- 用户会主动搜索、收藏或反复查看的教育、亲子、创作、生活方式和兴趣内容。

原生适配：

- 优先使用竖版 `2:3` 画布，并在制作时核对当前官方规格。
- 标题、画面文字和描述围绕一个可搜索的问题、任务或结果。
- 现有国内 2:3 封面只能复用构图与真实产品证据，不能直接翻译标题后发布。
- 产品截图和真实使用场景优先，生成式氛围不得虚构能力或用户效果。

### X

优先考虑：

- 独立开发、Build in Public、开发者工具、AI 产品和创始人观点。
- 有连续截图、GIF、短录屏、版本变化和具体开发决定的产品。

原生适配：

- 单帖版用一句明确判断或结果配一张图、GIF或短视频。
- Thread 版按起因、失败、决定、产品画面和结果推进。
- 开发故事写具体事件，避免只报里程碑和空泛创业感想。
- 长文版只在内容确实需要完整论证时使用，并核对账号功能。

### LinkedIn

优先考虑：

- 海外 ToB、专业服务、团队工作流、行业工具和创始人专业判断。
- 能展示岗位、业务过程、团队结果、案例和产品方法的内容。

原生适配：

- 开头点明岗位、业务情境或一个反常判断。
- 短帖保留清晰段落；文档轮播使用问题、流程、产品动作、结果和结论逐页推进。
- 视频用真人或旁白建立业务背景，再用产品录屏完成证明。
- 案例写清用户角色、原流程、产品动作和可见交付物。
- 文章版适合复杂方法、案例和产品决定，不直接复制博客正文。

### Reddit

优先考虑：

- 有高度相关 Subreddit，产品确实解决该社区长期讨论的问题。
- 创始人能提供完整经验、方法、技术细节或坦诚反馈请求。

原生适配：

- 先读取具体社区规则和已有高质量帖子。
- 标题描述问题、过程、结果或请求，不伪装成无关用户。
- 正文独立提供价值，透明说明与产品的关系。
- 使用社区熟悉的语言、案例和截图；不同 Subreddit 分别重写。
- 不把相同推广文案批量跨社区复制。

### Product Hunt

优先考虑：

- 已经可以使用或有明确可用路径的数字产品。
- 产品具有明确用途、新意、制作完成度或有趣体验。
- 能准备清楚的首图、产品画廊、短演示和 Maker Story。

原生适配：

- Tagline 一句话说清用户和核心结果。
- Gallery 按问题、产品动作、主要亮点和结果排列。
- Demo 聚焦第一次看产品的人怎样快速理解。
- Maker Comment 讲开发起因、关键决定、适合谁和希望讨论的问题。
- 这里只制作页面与内容素材，不提供发布日期、拉票或榜单策略。

### Hacker News / Show HN

优先考虑：

- 可实际体验、技术上有意思、面向开发者或具有清楚实现故事的产品。
- 创始人能讨论实现、取舍、限制和用户反馈。

原生适配：

- 标题直接说明做了什么，减少营销修饰。
- 首条说明产品用途、为什么做、技术或产品难点、当前限制和希望讨论的问题。
- 页面和演示要让技术读者快速验证产品。
- 发布前核对 Show HN 的当前资格与社区规则；这里只制作内容，不设计发布时间或投票动作。

### GitHub、Indie Hackers及专业社区

只在产品属性匹配时推荐：

- GitHub：开源项目、开发者工具、SDK、API 示例和可复现技术成果。
- Indie Hackers：独立开发过程、商业取舍、产品迭代和创始人经验。
- 设计、教育、创作者、行业论坛：当专业受众比泛平台更集中时使用。

这些版本需要围绕社区任务重写 README、演示、问题说明或开发故事，不能只丢产品链接。

### itch.io 与可玩产品平台

优先考虑：

- 可以在浏览器中直接运行或能够下载试玩的独立游戏、教育游戏和互动作品。
- 产品需要一个集中展示封面、截图、控制方式、玩法说明和 Demo 的页面。

原生适配：

- 页面先讲游戏体验、适合谁、怎样操作和实际内容，再补制作背景。
- 使用真实截图、清晰封面、简短描述、分类和准确 Tags。
- 浏览器版本尽量降低试玩门槛；精确文件、嵌入和索引规则在交付前核对官方文档。
- itch.io 是可玩分发页，不等于面向家长的内容主阵地，需要与短视频、图文或 YouTube 内容分工。

## 五、ToC 与 ToB 的平台组合

这些是判断起点，不是固定答案。

### 国内 ToC

常见候选：小红书、抖音、Bilibili、视频号，以及与品类高度相关的垂直社区。

- 结果视觉强、生活场景强：小红书或抖音优先。
- 需要完整教程或技术解释：Bilibili 优先。
- 信任与熟人传播重要：视频号优先。

### 国内 ToB

常见候选：视频号、公众号、知乎、Bilibili，以及行业社区。

- 决策依赖创始人和行业信任：视频号或公众号优先。
- 用户主动搜索专业问题：知乎优先。
- 产品需要完整工作流演示：Bilibili 优先。

### 海外 ToC

常见候选：TikTok、Instagram Reels、YouTube Shorts、Pinterest、YouTube、Reddit，以及品类社区；独立游戏或互动产品可以补充 itch.io。

- 几秒能看到结果：TikTok、Reels 或 Shorts 优先。
- 适合竖版图文、清单和视觉搜索：Pinterest 优先。
- 需要教程和搜索沉淀：YouTube 优先。
- 受众集中在兴趣社区：Reddit 或垂直社区优先。
- 可以直接试玩的独立游戏：itch.io 作为分发页，而不是唯一获客平台。

### 海外 ToB

常见候选：LinkedIn、YouTube、X、Reddit、Product Hunt，以及专业社区。

- 面向业务岗位和决策者：LinkedIn 优先。
- 面向开发者与早期技术用户：X、Reddit、Hacker News 或 GitHub 优先。
- 产品适合新品发现：Product Hunt 可作为内容页面之一，但不能代替持续的产品内容。

```text

标题或前三秒开头：
完整内容结构：

完整发布配文：
标签 Tags：

字幕与屏幕文字：

产品结果出现的位置：
结尾产品说明：
与其他平台版本的关键差异：
```

有效适配至少改变四项：标题或开头、内容结构、文字或口播、视觉顺序、信息密度、时长、产品出现方式。只改尺寸、平台名或标签不算适配。

Tags 也要平台原生：根据平台受众、内容形态和该条内容主题重写，不把国内标签翻译后直接用于海外，也不在三个国内平台机械复用同一组标签。

## 七、完整方案中的平台交付

`COMPLETE_PROMOTION_PACKAGE` 至少包括：

1. 一个主平台和两个备选平台的推荐卡。
2. 一到三个暂不优先平台及理由。
3. 六套图文和八套短视频各自的首选平台标注。
4. 前两篇完整图文分别改写为主平台和两个备选平台版本。
5. 前两条完整短视频分别改写为主平台和两个备选平台版本。
6. 每个平台版本的标题、内容描述、完整配文和 Tags。
7. 双市场或具备海外可能的产品，单列一个海外平台部分，说明可复用母题、本地化项、客户获客路线、产品发现/反馈路线和平台进入条件。

双市场产品先分别选择国内与海外的平台组合，再分别适配。不要把中文平台版本直译成海外版本。
