# 海外推广内容方向

这个参考文件负责海外内容语言和表达。具体平台推荐与平台原生改写同时读取 [platform-recommendation-and-adaptation.md](platform-recommendation-and-adaptation.md)；不要延伸到发布日历、转化、指标或复盘。

## 一、先确定具体市场

海外内容开始前写清：

- 主要国家或地区。
- 使用语言。
- 用户岗位或身份。
- 产品在当地通常被归入什么类别。
- 用户怎样称呼这项任务。
- 案例中的工作或生活环境。

不要使用一个模糊的“全球用户”概念。

### 双市场报告先回答能否复用

当报告已有国内内容池时，先说明：

- 可以复用的通常是产品机制、视觉钩子、真实操作和可见结果。
- 不能直接复用的通常是标题、正文、口播、年龄/年级说法、课程体系、单位、货币、案例背景、文化语境、Tags 与平台开头。
- “题目出现—用户操作—产品结果改变”这类证据链可以保留，但必须用目标市场熟悉的语言重新讲。

不要把国内内容笼统标记为“海内外通用”。如果尚未确定具体国家或语言，只给平台方向、本地化清单和进入条件，不假装已经完成海外获客文案。

## 二、重新写内容，不做直译

海外内容需要重新选择：

- 人物称呼。
- 任务名称。
- 工作流程。
- 时间、货币、单位和日期写法。
- 产品类别词。
- 标题节奏。
- 口播语气。
- 案例背景。
- 视觉信息密度。

中文内容中的情绪、比喻和网络用语不一定适合直接翻译。

## 三、海外 ToC 内容

### 重点人物

选择一个明确群体，例如独立创作者、学生、自由职业者、旅行者、家长或某类兴趣用户。

### 重点价值

- 一个具体任务怎样变简单。
- 产品结果是否立刻可见。
- 用户能创作、保存或分享什么。
- 产品是否减少重复动作。
- 产品体验有什么独特细节。

### 适合的故事

- 快速产品演示。
- 个人日常工作流。
- 一个清晰的前后变化。
- 创始人做产品的原因。
- 用户完成某个任务的过程。
- 一个可复制的教程。

### 图文感觉

- 标题直接写任务、人物或结果。
- 产品截图承担主要说明作用。
- 文字简洁，但场景不能丢失。
- 对比内容使用相同任务和相同输入。

### 视频感觉

- 尽早出现产品结果。
- 口播围绕一个问题。
- 屏幕文字使用当地用户熟悉的任务语言。
- 一条视频只展示一个主要结果。

## 四、海外 ToB 内容

### 重点人物

写清行业、公司规模、团队类型、使用岗位和管理岗位。

### 重点价值

- 具体工作流发生什么变化。
- 产品输出什么团队可用的材料。
- 使用者与管理者分别看到什么。
- 开发决定怎样服务专业场景。
- 产品怎样与原有工作方式相处。

### 适合的故事

- 一个岗位的典型任务。
- 一个团队从原材料到结果的过程。
- 产品工作原理的可视化解释。
- 匿名团队案例。
- 创始人对行业细节的理解。
- 产品版本变化和开发取舍。

### 图文感觉

- 场景、工作流和结果优先。
- 使用清晰流程图、产品界面和结果样张。
- 案例中写清角色、任务、产品动作和交付结果。

### 视频感觉

- 开头出现岗位和任务。
- 画面展示完整产品过程。
- 技术解释只保留理解产品所需的部分。
- 结果要让非开发岗位也能看懂。

## 五、海外混合产品

分别制作：

- 面向个人使用者的体验内容。
- 面向团队负责人的业务场景内容。

不要把个人便利和企业价值压缩进同一个标题或同一条短视频。

## 六、英文内容方向示例

### Scene-led

Start with the exact moment the user gets stuck.

### Result-led

Show the final artifact or visible change first.

### Build-led

Open with a failed version, removed feature, or product decision.

### Case-led

Name the user type, task, product action, and result.

### Tutorial-led

Promise one reproducible task and complete it on screen.

根据目标市场重新写完整句子，不把这些标签直接当最终标题。

## 七、海外平台路线

海外平台部分先按角色分组，再选择具体平台：

### 面向潜在客户

- 短视频触达：TikTok、Instagram Reels、YouTube Shorts。
- 图文与视觉搜索：Pinterest。
- 完整说明与搜索沉淀：YouTube。
- 垂直用户社区：与品类、职业、兴趣或使用场景高度相关的社区。

这些平台的标题、正文和画面始终直接面向潜在客户或实际使用者。完整推广包中的默认图文案例和视频案例只从这条路线选题，不加入开发日志。

### 面向产品发现与反馈

- 新品发现：Product Hunt。
- 社区验证：Reddit、Hacker News / Show HN、Indie Hackers。
- 开源或开发者分发：GitHub。
- 可玩产品和独立游戏分发：itch.io。

这条路线可以包含 Maker Story、实现取舍、限制和反馈请求，但必须与客户获客内容分开展示。Product Hunt、Show HN 或 Indie Hackers 的受众不等于产品的实际购买者，不能因为平台知名就把它们设为 ToC 获客主平台。

### 每条路线需要写清

- 平台在当前产品中的角色。
- 适合承载的内容和一个平台原生示例。
- 当前素材能否直接使用。
- 正式进入前必须具备的语言、页面、Demo、账号或社区条件。
- 不适合承担的任务。

这里只做平台方向和内容适配，不加入发布时间、发布节奏、转化、指标或复盘。
