# 推广方案 HTML 报告交付

完整推广方案优先交付为可直接浏览的响应式 HTML 报告，Markdown 只作为内部内容源或用户明确要求的附件。

## 信息结构

- 章节标题使用短标题，不在同一标题后追加解释句。
- 导航使用“内容池”“图文案例”“视频案例”等自然名称，不把数量写进导航。
- 双市场或具备海外可能的产品，导航中单列“海外平台”，并链接到一个完整章节；不要把海外方向藏在国内平台适配的结尾。
- 完整推广包在“海外平台”之后单列“Agent提示词”，用于把本报告沉淀为后续 Agent 可持续扩写的项目规则。
- 正文可以使用数据卡、图标、表格、筛选器、真实截图和可展开脚本降低阅读负担。
- 图文案例封面必须直接显示主标题。

## 章节标题版式

- 桌面端使用“左侧章节栏 + 右侧中文主标题与说明”的两列结构。左侧只放大号章节数字和英文标题，不使用独立的彩色圆角徽章或强调色卡片。
- 章节数字、英文标题和右侧中文主标题必须保持同色：浅色章节统一使用正文标题色，深色章节统一使用白色。不要让左栏使用紫色、薄荷绿或其他强调色而右侧使用黑白标题色。
- 章节数字和英文不能缩成装饰性小字。数字应明显放大，英文保持清晰可读；可参考桌面数字约 `48–52px`、英文约 `14px`，再根据字体和列宽微调。
- 左侧章节栏的高度由右侧“主标题 + 说明”内容块决定，不写死固定高度。数字顶部与右侧主标题顶部对齐，英文底部与右侧说明底部对齐；使用 `stretch` 和 `space-between` 等布局关系实现，不用单章硬编码偏移。
- 移动端可以把数字和英文收成横向紧凑标签，但仍须与中文主标题同色，并保持可读字号。

## 海外平台章节

- 先明确当前报告是国内优先、海外优先还是双市场，不把国内内容池笼统称为海内外通用。
- 用一块清晰判断说明哪些产品机制和视觉母题可以复用，哪些语言、课程体系、单位、货币、文化语境和平台文案必须本地化。
- 将平台按短视频触达、图文/搜索、新品发现、社区验证和实际分发分组。
- 把潜在客户获客与开发者/早期用户反馈分成两条路线，避免 Product Hunt、Show HN 或 Indie Hackers 与客户内容混写。
- 平台较多时优先使用角色卡和对照表，写清平台用途、适合内容、当前适合程度与必要条件；不加入日历、节奏、转化、指标或复盘。

## 图文案例

- 国内图文封面默认 `2:3` 竖版。
- 桌面宽度允许时一行三张，平板一行两张，手机一行一张。
- 生成式封面应以真实产品截图为参考，负责吸引力和构图；产品能力仍由真实截图和正文证明。
- 封面中的标题必须与案例主标题一致，不添加未经用户确认的评价、数据或效果。

## 内容池

- 完整包默认提供100个选题。
- 至少包含玩法、奖励、客户视角、题库、开发过程、实际使用者和强流量七类筛选；“强流量”紧跟在“实际使用者”之后。
- “实际使用者”使用真实使用者的语言、欲望、挑战和可见结果；儿童产品应包含儿童能理解并愿意点开的标题。
- “强流量”使用惊悚、夸张、冲突、反差或结果悬念放大真实玩法，但不得虚构能力、评价、效果、数据或不存在的后果。
- 对100个选题做整体去重和去水分，先删除空泛、重复、换词复述和开发者自嗨的角度，再补足数量。

## Agent 提示词章节

- 放在“海外平台”之后、最终总结之前，并加入顶部导航。
- 提示词正文之前必须有醒目的放置说明：推荐追加到实际产品项目根目录的 `AGENTS.md`；已有文件时只追加独立章节，不覆盖原规则。其他 Agent 则读取项目中的独立 `产品名-Agent内容创作提示词.md`。
- 使用结构化卡片呈现角色、产品事实、受众、内容池、标题规则、图文格式、视频格式和事实边界，避免一整屏密集纯文本。
- 提供“复制完整提示词”按钮，以及打开或下载独立 MD 的入口。
- 独立 MD 是当前产品专属提示词，不使用空占位符；提示词允许继续扩写任意合理数量的图文和完整短视频脚本。

## 验收

- 校验100个内容角度、6套图文案例和8套视频案例完整渲染。
- 校验七类筛选均可用，“强流量”只显示对应角度且筛选顺序正确。
- 校验所有本地图片加载成功。
- 校验桌面和手机没有横向溢出。
- 校验筛选、展开和复制等交互可用，控制台无错误。
- 存在海外平台章节时，校验导航锚点、平台分组、宽表横向滚动和手机端单列布局。
- 校验“Agent提示词”章节的导航、放置说明、复制按钮、独立 MD 链接和手机端单列布局。
- 校验所有章节的数字、英文和中文主标题颜色一致；桌面端左栏与右侧标题内容块顶部、底部对齐，长英文不裁切；移动端无横向溢出。
